1. Trust-Adjusted Utility Scoring (scoring.py)

After hard constraints filter out over-budget, slow, or below-floor bids, eligible bids are ranked by:

S_i = w_R * R_i - w_C * (Price_i / StageBudget) - w_T * (ETA_i / Deadline)
  • Why normalize by StageBudget instead of min-max across bids? Min-max turns a tiny 5-paise price difference into a full 1.0 penalty, which would let a cheap fabricator beat an honest provider.
  • Where does $R_i$ come from? Never from the provider's self-reported claimed_reliability (e.g., QuickClean claims 99%). It comes strictly from registry.reliability().

2. Bayesian Reputation with Decay (registry.py)

Every provider capability starts with a neutral $\text{Beta}(2, 2)$ prior ($R_0 = 0.500$). On every verifier verdict:

succ = 0.92 * succ + (1 if PASS else 0)
fail = 0.92 * fail + (1 if FAIL else 0)
R = (succ + 2.0) / (succ + fail + 4.0)
  • Cold-Start Run 1: QuickClean ($1.00, $R=0.50$) beats CleanCo ($2.00, $R=0.50$) on price, cheats, fails verification, gets ₹0, and drops to $R = 2.0 / 5.0 = 0.400$.
  • Learned Run 2: CleanCo ($R = 3.0 / 5.0 = 0.600$) immediately outscores QuickClean ($0.400$).

3. Double-Entry Escrow & Slashing (ledger.py)

Every credit movement is integer paise inside an atomic SQLite BEGIN IMMEDIATE transaction:

HOLD: user:demo → escrow:c-123 (Price + 5% Fee)
PASS: escrow:c-123 → agent:provider (Price) + platform:fees (Fee)
FAIL: escrow:c-123 → user:demo (100% Refund)
SLASH: bond:provider → platform:slashed (100 paise penalty)

Invariants Checked Live (/ledger/verify): Total Debits == Total Credits, no negative accounts (except system:mint), zero orphaned escrow on closed contracts, and 1-to-1 reconciliation with the SHA-256 audit log.
